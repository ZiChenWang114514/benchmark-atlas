# ScienceIDE-Hard

> Verification date: 2026-11-08. The access date is not the publication date or the run date; a field that cannot be confirmed remains Unverified.

ScienceIDE-Hard requires an agent to repair or rebuild an algorithm inside real scientific software and to deliver a modification that passes private numerical and physical checks. It is an evaluation subset of 85 tasks inside the ScienceIDE infrastructure, not every environment and training task; compiling, tests that run through, or a similar diff does not automatically equal scientific correctness.

Guide source: [Official materials](https://aitonomy.org/projects/scienceide) (accessed 2026-11-08); specific facts and historical access dates are given in the individual fields.

## Design goals

### Abilities measured

Algorithms are repaired and implemented in real scientific software and must satisfy domain numerical and physical contracts; this includes multi-file edits and convention-faithful reconstruction.

Sources: [1](https://arxiv.org/abs/2609.19134) (accessed 2026-11-08)

### Design background

Code unit tests and general program repair cannot adequately measure scientific numerical equivalence, conservation invariants, and complex domain conventions.

Sources: [1](https://arxiv.org/abs/2609.19134) (accessed 2026-11-08)

## Construction

### 题目或数据来源

Execution environments are built from scientific code repositories and official tests, and repair and implementation tasks are synthesized with runnable scientific checks; the Hard subset comes from five repository families.

Sources: [1](https://arxiv.org/abs/2609.19134) (accessed 2026-11-08)

### 出题背景

A scientific-computing and model-training team; the sources of the environments cover fluids, plasma, the ocean and the atmosphere, and other fields.

Sources: [1](https://arxiv.org/abs/2609.19134) (accessed 2026-11-08)

### Review process

Candidates are proposed first, and validity is then established by execution; each admitted task has a known-valid witness, an empty-delivery baseline, and a defective starting point.

Sources: [1](https://arxiv.org/abs/2609.19134) (accessed 2026-11-08)

### Quality control

Every public task has been verified by execution: the official fix scores 1.0 in the grading container, the unfixed build leaves room for reward, and the agent image contains no answer material.

Sources: [1](https://raw.githubusercontent.com/aitofound/ScienceIDE/main/README.md) (accessed 2026-11-07)

### 去污染措施

The same 85 task identifiers are fixed for every model; training and validation task identifiers do not overlap. Public source code is not the same as an absence of training exposure.

Sources: [1](https://arxiv.org/abs/2609.19134) (accessed 2026-11-08)

## Data format

### Size

Hard85 comes from 18 environments and 5 families of repositories: 52 repair tasks and 33 implementation tasks. The current preview publishes 30 and holds back 55. The infrastructure counts of 64 environments, 27 codebases, and 2812 training tasks are a different population of statistics.

Sources: [1](https://arxiv.org/pdf/2609.19134) (accessed 2026-11-08); [2](https://github.com/aitofound/ScienceIDE) (accessed 2026-11-08)

### Question types

Multi-step tool calls, repair and implementation of scientific code, delivering runnable changes.

Sources: [1](https://arxiv.org/abs/2609.19134) (accessed 2026-11-08)

### Modalities

Scientific source code, command lines, numeric output, and textual explanation.

Sources: [1](https://arxiv.org/abs/2609.19134) (accessed 2026-11-08)

### Languages

Languages of multi-science codebases in interaction with English; the language of each environment is in the source appendix.

Sources: [1](https://arxiv.org/abs/2609.19134) (accessed 2026-11-08)

### Difficulty

Difficulty is described by the unrepaired score, the number of edit locations, the verification cost, and the measured pass rate, rather than by one difficulty label assigned by hand.

Sources: [1](https://raw.githubusercontent.com/aitofound/ScienceIDE/main/README.md) (accessed 2026-11-07)

### 数据划分

Hard85: 30 items public and 55 items withheld; environment set: 15 public and 49 withheld. The two units of count must not be confused.

Sources: [1](https://raw.githubusercontent.com/aitofound/ScienceIDE/main/README.md) (accessed 2026-11-07)

## Evaluation

### Metrics

The strict success rate of scientific tasks; runtime, output tokens, and historically estimated cost are used as auxiliary analysis.

Sources: [1](https://arxiv.org/abs/2609.19134) (accessed 2026-11-08)

### Scoring

reward is the mean of the scores of the physical cases; reward_repair=max(0,(reward−floor)/(1−floor)), where floor is the score of the build that has not been repaired.

Sources: [1](https://raw.githubusercontent.com/aitofound/ScienceIDE/main/README.md) (accessed 2026-11-07)

### 提示与运行设置

15 model–harness combinations, a fixed 85 questions, and a budget of 1 hour per task; several repeats and a within-task bootstrap, with Fable run only once.

Sources: [1](https://arxiv.org/abs/2609.19134) (accessed 2026-11-08)

### 评测脚本

https://github.com/aitofound/ScienceIDE/tree/main/hard85

Sources: [1](https://raw.githubusercontent.com/aitofound/ScienceIDE/main/README.md) (accessed 2026-11-07)

### 可比性提醒

The model is coupled to the harness and to the tool budget; Fable is a single run, and the confidence intervals of Opus and Astra overlap. The time-truncation curve is a completion distribution computed after the fact, not a rerun under a new budget.

Sources: [1](https://arxiv.org/abs/2609.19134) (accessed 2026-11-08)
