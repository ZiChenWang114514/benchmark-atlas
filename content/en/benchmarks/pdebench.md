# PDEBench

> Benchmark Constitution, verification 2026-11-08. Unknowns remain "Unverified"; an access date is not an experiment date.

PDEBench is a suite for numerical field prediction and inverse problems in scientific machine learning, not a leaderboard of LLM physics question-answering accuracy. Its core is multi-equation simulation data that can be generated and archived, together with physics diagnostic errors; DaRUS data V8 and the CC-BY-4.0 license are filled in, and the original-paper baselines are kept by equation parameters.

Source: [Original description](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08); [Result evidence](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08)

## Design goals

### Abilities measured

Provides a time-dependent simulation evaluation across multiple partial differential equations for scientific machine learning.

Sources: [1](https://arxiv.org/abs/2210.07182) (accessed 2026-11-08， ) ; [2](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， )

### 设计背景与适用边界

Scientific machine-learning research often uses inconsistent equations, solvers, and evaluation metrics, which makes reproducible comparison difficult; PDEBench provides multidimensional PDE data and generators, together with metrics for data error and physical consistency.

Sources: [1](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， )

## Construction

### 题目或数据来源

Numerical simulation generates data for multiple sets of initial conditions, boundary conditions, and equation parameters, with accompanying data-generation code and machine-learning baselines.

Sources: [1](https://arxiv.org/abs/2210.07182) (accessed 2026-11-08， ) ; [2](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， )

### 构建者背景

The authors come from teams in scientific machine learning and in numerical simulation. Appendix K.3 of the paper lists Takamoto, Praditia, Leiteritz, MacKinlay, and Alesiani as having run the simulations. ANU Techlauncher assisted with part of the simulations.

Sources: [1](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， )

### Review process

This is not human question writing and review: trajectories are generated by a numerical solver from the equations, parameters, and boundary conditions, with a reproducible configuration attached; the 90/10 train-test split in the original paper is used for model comparison.

Sources: [1](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， )

### Quality control

A high-resolution numerical solution is used as the reference, and a generator, configurations, precomputed errors, and FAIR metadata are provided; the appendix acknowledges error from discretization. The notes for DaRUS V8 state that the advection solution and the Burgers solution have been corrected, and the version of the data cannot be ignored.

Sources: [1](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， ) ; [2](https://darus.uni-stuttgart.de/dataset.xhtml?persistentId=doi:10.18419/darus-2986) (accessed 2026-11-08， )

### 去污染与泄漏边界

The data are generated by numerical simulation and random initial conditions, not by scraping question-answer pairs from the web; the split into training and test is by sample. Public data is not the same as having finished a check for training overlap on every later model, and the files and versions used must be recorded.

Sources: [1](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， )

## Data format

### Size

Table 1 of the paper lists 11 "PDE × spatial dimension" configurations. Most 1D settings and Darcy have 10,000 entries per parameter configuration. 2D diffusion-reaction, 2D/incompressible NS, and shallow-water have 1,000 entries, and 3D compressible NS has 100 entries. Parameter combinations produce multiple files, and the numbers in the table cannot be taken directly as the deduplicated sample total of the whole library. The DaRUS V8 page lists 336 files.

Sources: [1](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， ) ; [2](https://darus.uni-stuttgart.de/dataset.xhtml?persistentId=doi:10.18419/darus-2986) (accessed 2026-11-08， )

### 题型与交付物

Forward prediction, long-time extrapolation, and inverse problems (recovering initial values/equation parameters) for numeric spatiotemporal fields; not natural-language multiple choice.

Sources: [1](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， )

### Modalities

HDF5 numerical tensors, with the axes conventionally sample N, time T, space X/Y/Z, and physical variable V; grid coordinates and equation parameters are also included.

Sources: [1](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， ) ; [2](https://darus.uni-stuttgart.de/dataset.xhtml?persistentId=doi:10.18419/darus-2986) (accessed 2026-11-08， )

### Languages

Not applicable to natural-language question-bank statistics: the core data are numerical fields; the documentation is in English, and the reference machine-learning implementation is Python/PyTorch.

Sources: [1](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， ) ; [2](https://github.com/pdebench/PDEBench) (accessed 2026-11-08， )

### Difficulty

Numerical difficulty is controlled through 1–3 dimensions, shocks and turbulence, multiple initial values, different boundary conditions, and parameter ranges; high-school, undergraduate, or LLM answer-difficulty tiers are not defined.

Sources: [1](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， )

### Public and hidden splits

The original experiment in §4.1 uses 90% for training and 10% for testing; Appendix K.2 speaks more broadly of the remaining 10% as validation or testing, and it states that users are not required to follow the split. The data are public, an experiment that reproduces the work should declare the split it uses, and a single hidden test cannot be invented.

Sources: [1](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， )

## Evaluation

### Metrics

RMSE, normalized RMSE, maximum error, and conservation, boundary, and frequency-band diagnostics for the applicable equations; reported separately by equation and by task.

Sources: [1](https://arxiv.org/abs/2608.22504) (accessed 2026-11-07， )

### Scoring

RMSE, nRMSE, max error, cRMSE, bRMSE, and low-frequency, mid-frequency, and high-frequency fRMSE are computed between the predicted field and the numerical reference, equation by equation, parameter by parameter, and task by task. Lower error is better. Scores from different equations are not averaged into an LLM accuracy.

Sources: [1](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， )

### 提示与运行设置

This is not an evaluation that prompts an LLM. FNO is trained under the protocol of the original implementation. U-Net uses the autoregressive training variant and the pushforward training variant. PINN is based on DeepXDE, and each condition has to be trained again. The experiments in the paper use a 90/10 split. Resolution in space and time, and the parameters of the equation, change with the configuration.

Sources: [1](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， )

### 评测脚本

train_models_forward.py, train_models_inverse.py, and metrics.py under pdebench/models. The actual paths and configurations follow the repository documentation.

Sources: [1](https://github.com/pdebench/PDEBench) (accessed 2026-11-08， )

### 可比性提醒

The equation, parameters, grid and time resolution, forecast lead time, data-release version, and split must be the same. Lower errors such as nRMSE are better. Per-condition PINN fitting and cross-sample FNO and U-Net have different costs, and tasks are not merged across one another under a single claim of “first on the overall leaderboard.”

Sources: [1](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， ) ; [2](https://darus.uni-stuttgart.de/dataset.xhtml?persistentId=doi:10.18419/darus-2986) (accessed 2026-11-08， )

### 饱和程度

No single natural-language accuracy, and no saturation threshold, is defined; the paper’s baselines still have error under shock waves, parameter extrapolation, and long-term stability. An improvement can be discussed only inside a fixed equation and a fixed error metric.

Sources: [1](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， )

### 争议与已知问题

Data V8 contains corrections to the advection solution and to the Burgers solution. A baseline from the older paper has to keep the historical scope of its data. Section 4.1 and the appendix do not word the remaining 10%, as test or as validation, in exactly the same way. The repository warns that the Hydra data_path changes and that dependencies may not be compatible. Both affect whether a run can be reproduced.

Sources: [1](https://darus.uni-stuttgart.de/dataset.xhtml?persistentId=doi:10.18419/darus-2986) (accessed 2026-11-08， ) ; [2](https://arxiv.org/pdf/2210.07182) (accessed 2026-11-08， ) ; [3](https://github.com/pdebench/PDEBench) (accessed 2026-11-08， )

### 衍生与后续使用

The official README lists later work that uses the data: Active Learning for Neural PDE Solvers (ICLR2025) and LOGLO-FNO (TMLR2025). They are papers on methods or on use of the data, and they are not automatically treated as a new data version or as an independent benchmark.

Sources: [1](https://github.com/pdebench/PDEBench) (accessed 2026-11-08， )
